## 1. 本文新增的事实（本轮当场跑，不是复述质检）

**1.1 三行「截字」证据确实量的不是候选词。** 按 `fs115.py:36 ink_extent` 同一算法（`x0=16 x1=1064 thr=45 cnt>=2`）重测交付附件 `f440_1.15_c.png` 的候选带 `y=1352..1478`：

```
bg (244, 245, 247) nrows 49
ink_top 1397 ink_bot 1445 ink_h 49
cols min 42 max 206      ← 命中列全部落在 chip 宽度内
cols>240 count 0
x-runs [(42, 206)]       ← 整带只有 1 个墨迹段 = 组合码 chip
```

`ink_top/ink_bot` 与入库值逐字节一致 —— 数字没错，对象错了。另两张（从 `665ddcc` 的 `shots/` 取出）：`f440_1.0_c_cand.png` = 1 段 (42,186) chip-only；`f520_1.15_c_cand.png` = chip (50,140) + **1 条**候选 (206,432)，带内其余 ~650px 空白。三轮的候选池都是空的。

**1.2 作废范围比质检写的更宽（本文的核心裁决）。** `CandidateView.kt:76-77`：候选列表为空时 `scrollView.visibility = View.GONE`。所以 `fs115.py` 那三轮的「组合态」其实是 **chip-only 态**，而规格 AC-1 的 Given 写的是「输入 4 个字母形成组合（**有候选**）」（spec `:400`）。

→ 「空态 988px → chip-only 988px，Δ=0」是**同义反复**：两态本来都没有候选行内容，46dp 钉高当然不涨。**恒高契约（AC-1，本轮采纳项之一）至今没有被有效测过一次**，不只是 §4 的截字读数。作废清单必须覆盖 §3 的 AC-1 三组 Δ 与 §4 三行，二者同因同批。

**1.3 「≥4 个候选」不是不可达门限。** 520dpi/fs1.15 实测 3 字候选字身墨迹 226px（≈75px/字），chip 右沿到采样右界约 911px → 可容 ~6 条 3 字词。所以 §5 敢直接立 AC，不必先把规格放宽。

## 5. 打回项 5：§2.1「至少完整显示 4 个候选」升格为 spec-AC-10

裁决：**升格为 AC，编号 `spec-AC-10`，本轮必测**（与打回项 1 同批跑，边际成本≈0）。

理由：spec `:215` 这句不是愿望清单，是 §2.1 单行改造的**规范性副作用约束**（「规格要求……并保证至少完整显示 4 个候选；不足时优先牺牲 chip 的显示宽度而不是候选数」）。本轮采纳了「恒高 46dp + 去掉翻页」，却没核过它换来的横向空间代价 —— 不测等于这笔账没对过。§1.3 的几何预核说明它可达，所以立 AC 不是给 PR #18 预设罪名。

判据（可直接抄进规格与报告，第三人可复跑）：

> ⚠️ **订正（11-17 第五轮，见 §9.2）**：下面这段判据正文里「工装断言成立」的三条 Given 已被 UX 收进规格 `8324b03:525`（改写成 ①②③，未增未减），**从本节起判据正文以规格为准**（§9.0 立的规矩：裁决文档不复制判据正文）。本文 §6-1 那句「chip==所敲串 **且** 候选数 ≥4」多塞了一条，把 AC-10a 的结论写成了前置条件 —— 那一半作废，闸门只守 Given 三条，`≥4` 只进 `AC10` 判定行。
```
Given  iSpeech 为默认输入法，宿主输入框聚焦，键盘已弹出；敲入一个组合码，且工装断言成立：
       chip 文本 == 所敲串、候选条可见（scrollView VISIBLE）、候选池 ≥ 8 条
       任一不成立 → GATE 非零退出，不得出数（这是打回项 1 的闸门，二者共用）
When   两档各截一帧组合态：440dpi / font_scale 1.0 与 520dpi / font_scale 1.15
       采样区 x ∈ [chip 右沿 + 1, 1080 − paddingEnd]，y = 候选带内沿（46dp 内、去掉上下 4dp padding）
Then   字身墨迹完整可见的候选项数 ≥ 4
       「完整」= 左右都不越采样区、上下都不与带内沿相切、该项未被 ellipsize
And    逐条打：x0 / x1 / 字身墨迹 top / bot / 该项 pitch；数字角标圆片不计入字身
```

### 9.2 打回项 2：闸门只守 Given，`≥4` 只进 AC-10a 判定 —— 采纳；错在我

**出处纠正是我的**：本文 §5 的 Given 只有三条（① chip==所敲串 ② 候选行在位、非 chip-only ③ 池 ≥8），UX 已把这三条原样收进规格 `:525`（未增未减）；但我在 §6-1 写闸门形状时多塞了一条「候选数 ≥4」。工装照 §6-1 实现，于是**闸门把 AC-10a 的结论当成了前置条件**——AC-10 只会「不给数」，永远不会「出 FAIL」。一个测不出失败的判据等于没有判据。

**自本节起 §6-1 那句话作废一半：闸门 = 「chip==所敲串」+「`cand_count ≥ 1`（= Given ②）」+「池 ≥8（= Given ③）」。`≥4` 退出闸门，只留在 `AC10` 判定行。** 三条硬要求（只给形状，脚本怎么改测试工程师选）：

1. **`MIN_CAND` 降到 1，但那一档不许删。** 事实：`band.py:113/188` —— `analyze()` 只在「找不到 chip 填充」时 `ok=False`，`cand_count==0` 的 chip-only 帧照样返回 `ok=True`。今天挡住第四轮「量错对象」的只有 `fs115.py:117` 这一条。若连分支一起删，chip-only 帧会一路走到 `pool_low`（rc=14），失效原因从「量错对象」变成「词库不够」，第三人照 §10 复跑会读错。→ `rc=13` 保留，语义改成「`cand_count==0` = 候选行不在位」，`README.md:36` 退出码表同行改。
   - **顺带纠 `README.md` 一处既有错标注**：rc=11 那行写的是「chip 右侧一个候选字身都没有」，但代码里 rc=11 挂在 `not a["ok"]`（= `no_chip_fill`，**chip 盒本身没找到**）上；「chip 在、候选 0 条」今天走的是 rc=13。两行语义要分开写死：**11 = 连 chip 都没画出来；13 = 有 chip、候选 0 条（chip-only）**。否则「拒绝出数」的两种原因会被读成同一种。
2. **`≥4` 是 `full_count` 的门限，`≥8` 是池的门限，不可互换。** 池 ≥8 正是 AC-10a 的**可判性来源**：词库里明明有 ≥8 条，屏上凑不满 4 条完整可见 = 横向空间不够 = FAIL。所以 `cand_count < 4` **不是**「不给数」的理由，它就是 FAIL 本身。这条把质检在风险 3(b) 里挂的问题关掉：不存在「不足 4 条时怎么判」的空档。
3. **判定与处置分开，AC-10b 不是免判通道。** AC-10a 对**每一帧**出 verdict（两档 × 两码 = 4 帧）；AC-10b 记同一批帧的逐项 x0/x1/字身 top/bot/pitch 与词长归因。→ `dashu@520dpi·fs1.15` 的期望出数是**两行**：`AC10 … cand=3 full_count=3 verdict=FAIL` **＋** `AC10b … recorded reason=long_word_budget`。质检给的形状只有 AC10b 一行，少一行，按本节。
   - **这不是把 D3 判得更重**：D3 早已 FAIL（`shijian` 那帧），本条只是不让第二帧静默。
   - 反向同样禁止：**不许看完结果再挑样本**。报告在 440 档把 `shijian`/`dashu` 两码都当 AC-10a 样本判过 PASS，同一批码在 520 档必须同样判，不能以「这码是长词、属 AC-10b」为由摘出去。

### 9.3 打回项 4：本链标签用 **FAIL** 档

派工 §五的三档是**判定树不是菜单**：FAIL（判据不满足）优先于条件性 no-go（真机口径缺失）。本轮模拟器口径内有两条规格 AC 判 FAIL（AC-2 硬件/注入键路径 = D1、spec-AC-10a@520dpi·fs1.15 = D3），真机 pp 未定稿是**另外**一条附加缺口。

裁决：表头写
**`FAIL（判据不满足：spec-AC-2 硬件/注入键路径、spec-AC-10a @520dpi·fs1.15）＋ 真机 pp 未定稿（附加缺口，非主因）`**

为什么不给「条件性 no-go」通融（唯一的实质理由）：那个标签的含义是「补上缺的口径就能解锁」。本链补设备解锁不了——**D3 的失败档 520dpi/fs1.15 就是真机参数**（上真机只会把它坐实），D1 与设备无关。标签错一档，合并窗口里就会把「还差一台手机」当解锁条件。**不重测**：这是标签与文字问题，取数面本轮已够（质检同判）。同时 §1 把三档定义各写一行，并加一句「本标签含义：即使真机到位也不得 go」。

**顺带关掉质检升级给「人裁」的第 ② 条（硬件键算不算 AC-2 范围）——它归我，不用等人。** 规格 AC-2 的 When 是「在 300ms 内连按两次空格键」（`8324b03:431`），**没有任何软键限定**；同一份规格 §5 `:589` 自己写「外接键盘与物理键盘同样走这条」。按现行文本，硬件/注入键在 AC-2 面内 → **D1 = AC-2 判据 FAIL，维持 P1**。UX 若认为物理键盘不属本期范围，那是**范围缩减**：改规格 When 加「软键盘」+ PM 确认，然后回改报告判定行；**不追溯本轮**（本轮测的就是现状）。不接受「取证按 keyevent、判定按软键」两头都占。
