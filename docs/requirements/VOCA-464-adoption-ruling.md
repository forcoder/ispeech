# VOCA-464 · 520dpi·fs1.15 采纳面裁决（D3 出口）

裁决人：UX设计师（本单 owner）。触发：父单 VOCA-37 风险 **R17**（A/B 任一 AC FAIL → 24h 内拉 UX + UI + PM 裁采纳面让步）。
输入事实：VOCA-47 第六轮取证（PR #25 head `5e8b0f4`）+ 代码常量（PR #18 head `c524351`）+ 本单现算 `tools/qa/voca-37/ac10_budget.py`。
落纸：`docs/keyboard-ux-spec.md` 的 diff 随本文件一起进 **PR #17**（与已排期的三项规格改动同一 PR，不拆）。
**本裁决不改一行产品代码、不重测、不判任何测试对错。**

## 0. 结论

**选 ③（判据分档：档1 逻辑宽度 ≥371 dp 仍要求完整 4 条；档2 <371 dp 要求完整 3 条 + 溢出可见），并附一条让步前置：先把「溢出可见」立成 AC-12。**

①②④ 三条不是「不选」，是**几何上不可达**：现算给出被测档缺 **38.3 dp**，而 ① 最多省 23.1 dp（且要把 chip 压到只剩 ≈2.0 位可读码）、② 需要再多 24.5 dp、④ **横向增益 0 dp**。

同时，本单把三角里**一条假的边**去掉：「命中高度 ≥48 dp」来自对 WCAG 2.2 AA 2.5.8 的误引（真门限 24×24 CSS px），改成「填满 46 dp 恒高带」后**零宽度成本、零高度成本**，与候选数不构成互斥。

**这条裁决的真实让步面比 D3 的登记要小**：FAIL 是**被测几何**造出来的（1080 px 宽 @520 dpi = 332 dp，市面上不存在这种屏）。按需求 I3 指定的目标真机 ALN-AL00（1260×2720@520 = **387.7 dp**）现算，**过档1、第 4 条完整可见**，产品侧一条没少给。所以 ③ 不是「把 4 改成 3」，是「给判据按几何加一档」，让步只落在窄面板尾部。

## 1. 事实基础与现算口径（可复核）

`tools/qa/voca-37/ac10_budget.py` 只读两份证据文本，不读产品代码、不改判据数据；口径全部写死在脚本常量里。

| 口径 | 值 | 来源 |
|---|---|---|
| 项宽 | `x1 − x0 + 1`（**盒子**，自带项内 `dp(12)`×2 与项间 `dp(6)`） | `ev_r6_ac10_decoupled.txt` 的 `CAND` 行；`CandidateView.kt`（`c524351`）`setPadding(dp(12),dp(6),dp(12),dp(6))` / `marginEnd = dp(6)` |
| 完整数 | 只算 `fully_visible=True` 的项；被视口切掉的不进完整数 | 同上 `fully_visible` / `reason=viewport_clip` |
| 第 4 条补齐宽 | 同帧 **2 字项的中位宽**（225 px = 69.2 dp） | AC-10a 原文「2–3 字常用词为主」；长词不进硬门限 |
| 所需逻辑宽度 | `paddingStart 8 + chip 盒 + Σ(4 项) + paddingEnd 6` | `candidate_view.xml:14-17`（`c524351`）根 padding |
| dp↔px | `density/160`；字号缩放由帧本身带入（帧就是 fs1.15 截的） | 证据行 `dens` / `fs` |
| 采样右界 | `1080 − paddingEnd` = 1060 px @520（另给屏宽口径 1080 对照） | 规格 AC-10 采样区定义 |

**现算结果**（完整原文见本单交付评论）：

| 帧 | chip 盒 | 各项盒子 px | 需要的逻辑宽度 |
|---|---|---|---|
| `shijian` @520·fs1.15 | 214 px = 65.8 dp | 270 / 225 / 225（完整）+ 第 4 条按 225 补 | **370.6 dp → 规格取 371 dp** |
| `dashu` @520·fs1.15 | 200 px = 61.5 dp | 206 / 353（4 字）/ 225 + 第 4 条按 225 补 | 386.0 dp（含长词 → AC-10b 只记录） |

右沿落点与被切掉的数量，与 PM 登记 D3 时给的算术**逐位一致**：1185 px（距屏宽缺 105 px、距采样右界缺 125 px）与 1235 px（缺 155 / 175 px）。

| 几何 | 逻辑宽 | 对 371 dp 的余量 | 判档 |
|---|---|---|---|
| 1080×2340 @440 | 392.7 dp | **+22.1** | 档1 ≥4 ← 第六轮 440 四组全 PASS |
| **1080×2400 @520（被测档）** | 332.3 dp | **−38.3** | 档2 ≥3 ← 第六轮 520 两码 FAIL |
| 1080×2400 @480 / @560 | 360.0 / 308.6 dp | −10.6 / −62.0 | 档2 ≥3 |
| **1260×2720 @520（目标真机）** | 387.7 dp | **+17.1** | **档1 ≥4**（第 4 条右沿 1185 px，距屏右 75 px） |
| 1440×3200 @560 | 411.4 dp | +40.8 | 档1 ≥4 |

**这条线一次性解释了同一轮的两种读数**：392.7 > 371 > 332.3 —— 440 过、520 挂，不是"密度玄学"，是逻辑宽度跨过了门限。旧规格 §9.1 那条「可达性预核」算错过（按字身 226 px/项估「可容 ~6 条」，漏了每项 98 px 的 padding+margin；按盒子 911÷270 = 3.37 条），本单已在 AC-10 原地订正，**口径订正：横向预算用盒子，不用字身**。

## 2. 为什么是 ③：四条出路的可达性

| 出路 | 现算（被测档缺 38.3 dp） | 判定 |
|---|---|---|
| ① 缩 chip | chip 盒 65.8 dp（`shijian`，7 位）／61.5 dp（`dashu`，5 位）；扣掉自身 12 dp padding 后 7.69 dp/位。**保住 4 位满码**（五笔满码是底线）的下限是 42.8 dp → 最多省 **23.1 dp < 38.3 dp**。要补齐缺口得把 chip 压到 **27.5 dp**（文本 15.5 dp ≈ **2.0 位**）；即便按整屏宽口径（缺 32.3 dp）也只到 **2.8 位**，且 5 位以上拼音码必然截断 | **不可达**，且代价不可接受：chip 是屏幕上唯一告诉用户「我现在敲的是什么」的地方；截了它，第 4 条看得见也不知道该不该点 |
| ② 放宽 §2.1 词长 | 若被选中，新分布口径得写成：**硬门限只看前 4 项盒子宽度之和 ≤ 可用宽度，且这 4 项全部为 2 字词（即 §2.1 的「2–3 字常用词为主」收紧为「以 2 字词为准，3 字及以上一律进 AC-10b 只记录」）**。按实测 2 字项盒子 225 px 现算：全 2 字需要 **356.8 dp**，可用 **332.3 dp** → 还差 24.5 dp | **不可达**：词长口径已经兜在 2–3 字（AC-10a 原文），再兜就没词可兜了 —— 这是在改输入法的产品形态，不是在改判据；而且「只出两字词」的输入法本身就不合格 |
| ③ 判据分档（档2 = 完整 3 条 + 溢出可见） | 不需要额外宽度 | **唯一可达**。属**判据让步** → §3 的签字要求 |
| ④ 动恒高 46 dp | 横向增益 **0 dp**（高度不换宽度）。竖向也无富余：46 dp = 上下各 4 dp + 38 dp 内容（`minHeight 38dp`），fs1.15 实测内容 105~121 px、底部余量只剩 19 px@440 / 24 px@520 | **不可达且有害**：加高同时打破 AC-1（恒高契约）与 pp，正是本单非功能约束「不得为了凑候选数把候选条加高」禁止的那件事 |

## 4. ③ 的成立条件：档2 必须绑定「溢出可见」（新立 AC-12）

「只能看 3 条」这件事，**只有在用户看得见「后面还有」的时候才不伤人**。实测：

- `shijian` @520 第 4 条 `x=961..1059`、`fully_visible=False`、`badge_clipped=True`，**字身只剩 11.4 dp（37 px）= 一个字的三分之一**（正常 2 字项字身 36.0~36.6 dp）；
- `dashu` @520 `cand_count=3` —— 第 4 条**一像素都没进视口**；
- VOCA-185 之后翻页器 / 齿轮 / 页码全部移除、`overScrollMode=never`（`c524351`），横滚**没有任何静止态可视线索**。

结论：没有 AC-12，档2 的实际体验是「用户以为只有 3 个词」，然后直接打下一码把后面挤掉 —— 这比 D3 登记的缺陷本身更伤可用性。**所以 AC-12 是档2 的成立条件，不是附带建议**：AC-12 不达标 ⇒ 档2 不成立 ⇒ 只能回代码让步（①/②），而 ①② 已证不可达 ⇒ 那时才真的需要动恒高（④），而那件事被本单非功能约束禁止。这条链条是本次裁决的**自我约束**，写进规格防止后来者拿档2 当免费午餐。

AC-12 本轮**不进 W5 门槛**（与 AC-11 同处置：不在 PR #18 变更面内，立它进门槛会让闸门凭空多一个 FAIL），交实现单。

## 5. 三角里那条假的边：命中高度 ≥48 dp

规格 §5 旧行写「候选项命中高度 ≥ 48 dp（WCAG 2.2 AA 2.5.8 / Material）」，并把「≥48 命中」与「恒高 46 dp」当作互斥的两条边。**两处都不成立**：

1. **出处误引**：WCAG 2.2 AA 的 **2.5.8 Target Size (Minimum) 是 24×24 CSS px**；44×44 是 **AAA 的 2.5.5**；48 dp 是 **Material 的建议值**。实测候选内容带 38.2 dp 早就过了 24 px 那条线 —— 我们原来在给自己加一条标准没有的要求，还把它当成第三条约束。
2. **恒高内本来就有空间**：46 dp 带 = 上下各 4 dp padding + 38 dp 内容（`minHeight 38dp`）；440 dpi 下 46 dp = 126 px，实测内容 105 px，**21 px ≈ 7.8 dp 的行内余量**可以把触摸命中框从 38.2 dp 抬到 **46 dp**，不动恒高、不动宽度、不动 pp。

**订正后的规格**：硬门限 = **命中高度填满 46 dp 恒高带**；48 dp 降为「不增长度前提下的目标值」，只能在带外上下各 ≤2 dp 的溢出里实现，**须 UI 确认溢出方向与视觉余量后才算达标**，不得为凑 48 dp 改带高。收益：AC-11 的误上屏面同时缩小（有效命中区从 105 px → 126 px 是同一处几何改动，与 slop 修复同批最省）。

## 7. pp：本单不裁，但把口径钉住（防止拿档位一起免掉）

pp 与 AC-10 在第六轮同时 FAIL，**同因不同轴**：同一机制（dp/sp 布局不随物理密度收敛），但候选数对**逻辑宽度**敏感、pp 对**高度比例**敏感。搬到目标真机几何后 **AC-10 翻 PASS、pp 不翻**（同 520 dpi 下 IME 高度就是帧值 1168 px；1168÷2720 = 42.9 % vs 搜狗 1002÷2720 = 36.8 % → 仍差 **+6.1 pp**，而门槛是 ≤1 pp）。

三条口径写进规格 §6.5：① pp 判据必须是**比率或 dp**，不得用模拟器像素高差跨档比较；② **pp 不得用候选条高度来还**（本单非功能约束的反向版）；③ 档位改动**不免除** pp 的账。pp 的修复方向在键区（§6.2 方案 B1：恒高 + 键高 52→46）与工具栏，属**架构 + UI + 前端**的变更，需要 ADR 与真机取证 —— **不在本单范围，建议由 PM 单列一条 R17 后续项**。
