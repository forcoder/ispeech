# VOCA-464 · 520dpi·fs1.15 采纳面裁决（D3 出口）

裁决人：UX设计师（本单 owner）。触发：父单 VOCA-37 风险 **R17**（A/B 任一 AC FAIL → 24h 内拉 UX + UI + PM 裁采纳面让步）。
输入事实：VOCA-47 第六轮取证（PR #25 head `5e8b0f4`）+ 代码常量（**取证时** PR #18 head `c524351`；现 head `78343a4` = VOCA-465 D1，`git diff --name-only c524351 78343a4` 里**没有** `candidate_view.xml` 与 `CandidateView.kt` ⇒ 本裁决依赖的 46 dp 带、padding 8/6、`setPadding(12,6,12,6)`、`marginEnd 6`、`minHeight 38dp`、`overScrollMode=never` 在新 head 上逐字未变，**预算不需重算**）+ 本单现算 `tools/qa/voca-37/ac10_budget.py`。
落纸：`docs/keyboard-ux-spec.md` 的 diff 随本文件一起进 **PR #17**（与已排期的三项规格改动同一 PR，不拆）。
**本裁决不改一行产品代码、不重测、不判任何测试对错。**
**2026-11-17 质检后的适用范围订正**：本文件 ① 的「不可达」原判给整个档2，实际只对**缺宽 > 23.1 dp（逻辑宽 <347.5 dp）**成立；判据（两档 + AC-12）与 ③ 的选择不变，被订正的是「哪条出路在哪个宽度区间可用」。详见 §2 表的「适用范围」列与 §4 的退路表。

## 0. 结论

**选 ③（判据分档：档1 逻辑宽度 ≥371 dp 仍要求完整 4 条；档2 <371 dp 要求完整 3 条 + 溢出可见），并附一条让步前置：先把「溢出可见」立成 AC-12。**

①②④ 三条不是「不选」，是**在被测档上几何不可达**：现算给出被测档（332.3 dp）缺 **38.3 dp**，而 ① 最多省 23.1 dp（再省就要把组合码截到 4 位以下）、② 需要再多 24.5 dp、④ **横向增益 0 dp**。三条的适用范围不同，不是一句话打包：

| 出路 | 不可达成立的区间 | 依据 |
|---|---|---|
| ① 缩 chip | **只对逻辑宽 <347.5 dp**（= 371 − 23.1）。347.5~371 dp 的档2 面板 ① **可达**：360.0 dp 处 chip 收到 55.2 dp、仍可读 5.6 位 > 4 位底线 | §2 表现算 + `ac10_budget.py` 的「① 可达边界」行 |
| ② 放宽词长 | <356.8 dp；但 356.8 > 347.5 ⇒ **凡 ② 可达处 ① 必可达**，② 被 ① 全区间支配，没有只有 ② 能救的面板 | 同上 |
| ④ 动恒高 | **所有几何**（0 dp 与面板宽无关），且同时破 AC-1 与 pp ⇒ 本单非功能约束禁止 | §2 表 + 本单约束 |

**这不翻转 ③**：被测档 332.3 dp < 347.5 dp，① 对它确实不可达，「前 4 条完整可见」在**已入库证据指向的那块面板**上仍然只能靠判据分档拿到。订正的作用是让后来者别把「①②④ 都够不着」签成一句对全体档2 的话 —— 人签字时读到的前提必须与证据同范围。

同时，本单把三角里**一条假的边**去掉：「命中高度 ≥48 dp」来自对 WCAG 2.2 AA 2.5.8 的误引（真门限 24×24 CSS px），改成「填满 46 dp 恒高带」后**零宽度成本、零高度成本**，与候选数不构成互斥。

**这条裁决的真实让步面比 D3 的登记要小，但比「尾部」大**：FAIL 是**被测几何**造出来的（1080 px 宽 @520 dpi = 332 dp，市面上不存在这种屏）。按需求 I3 指定的目标真机 ALN-AL00（1260×2720@520 = **387.7 dp**）现算，**过档1、第 4 条完整可见**，产品侧一条没少给。所以 ③ 不是「把 4 改成 3」，是「给判据按几何加一档」。**让步落在谁身上要说准**（旧文字写「只落在窄面板尾部」，口径不准）：档2 覆盖 **<371 dp**，其中 **360.0 dp 是 Android 的 `sw360dp` 主流档**（1080×1920 / 1080×2400 @480 都在这），不是白牌尾部。准确说法 = **对本次发版不生效**（本项目声明的目标真机只有 ALN-AL00，`docs/keyboard-ui.md:10` 与本规格头部量测设备，387.7 dp 走档1）；**对 347.5~371 dp 的面板生效，但那一段 ① 是可达退路**；真正「只能靠降判据」的区间是 **<347.5 dp**。规格是长期文档，按这三段写才不会把「让步面窄」读成「让步面不存在」。

## 2. 为什么是 ③：四条出路的可达性

**下表「判定」列的对象是被测档（332.3 dp、缺 38.3 dp）**。①② 各有一条与宽度绑定的可达边界，最后一列写清它在哪个区间成立 —— 把「被测档不可达」写成「对全体档2 不可达」就是把裁决的前提超出证据（2026-11-17 质检打回项 1）。

| 出路 | 现算（被测档缺 38.3 dp） | 判定 | 适用范围（不可达成立的区间） |
|---|---|---|---|
| ① 缩 chip | chip 盒 65.8 dp（`shijian`，7 位）／61.5 dp（`dashu`，5 位）；扣掉自身 12 dp padding 后 7.69 dp/位。**保住 4 位满码**（五笔满码是底线）的下限是 42.8 dp → 最多省 **23.1 dp < 38.3 dp**。要补齐缺口得把 chip 压到 **27.5 dp**（文本 15.5 dp ≈ **2.0 位**）；即便按整屏宽口径（缺 32.3 dp）也只到 **2.8 位**，且 5 位以上拼音码必然截断 | **被测档不可达**，且代价不可接受：chip 是屏幕上唯一告诉用户「我现在敲的是什么」的地方；截了它，第 4 条看得见也不知道该不该点 | **仅逻辑宽 <347.5 dp**（= 371 − 23.1）。≥347.5 dp 时省下的宽度就够补差、chip 仍 ≥42.8 dp／4 位：360.0 dp 处收到 **55.2 dp／5.6 位**，满足 §2.1 让步顺序 #3 自设的「不得截到 4 位以下」⇒ **① 可达** |
| ② 放宽 §2.1 词长 | 若被选中，新分布口径得写成：**硬门限只看前 4 项盒子宽度之和 ≤ 可用宽度，且这 4 项全部为 2 字词（即 §2.1 的「2–3 字常用词为主」收紧为「以 2 字词为准，3 字及以上一律进 AC-10b 只记录」）**。按实测 2 字项盒子 225 px 现算：全 2 字需要 **356.8 dp**，可用 **332.3 dp** → 还差 24.5 dp | **被测档不可达**：词长口径已经兜在 2–3 字（AC-10a 原文），再兜就没词可兜了 —— 这是在改输入法的产品形态，不是在改判据；而且「只出两字词」的输入法本身就不合格 | 边界 <356.8 dp；但 356.8 > 347.5 ⇒ **凡 ② 可达处 ① 必可达且 ① 不改产品形态**，所以 ② 被 ① 全区间支配，不存在「只有 ② 能救」的面板。**② 的死因是被支配，不是某个宽度不够** |
| ③ 判据分档（档2 = 完整 3 条 + 溢出可见） | 不需要额外宽度 | **被测档唯一可达**。属**判据让步** → §3 的签字要求 | 全宽度适用（不改几何），但在 ≥347.5 dp 段与 ① 重叠 —— 那里 ① 能保住 4 条，让步代价更小；**签字时请按「③ 是被测档与 <347.5 dp 面板的唯一出路」理解，不是「全体档2 的唯一出路」** |
| ④ 动恒高 46 dp | 横向增益 **0 dp**（高度不换宽度）。竖向也无富余：46 dp = 上下各 4 dp + 38 dp 内容（`minHeight 38dp`），fs1.15 实测内容 105~121 px、底部余量只剩 19 px@440 / 24 px@520 | **不可达且有害**：加高同时打破 AC-1（恒高契约）与 pp，正是本单非功能约束「不得为了凑候选数把候选条加高」禁止的那件事 | **所有几何都不可达** —— 0 dp 与面板宽无关。这是四条里唯一不带区间的判定，也是任何退路链条都不该指向它的原因 |

## 4. ③ 的成立条件：档2 必须绑定「溢出可见」（新立 AC-12）

「只能看 3 条」这件事，**只有在用户看得见「后面还有」的时候才不伤人**。实测：

- `shijian` @520 第 4 条 `x=961..1059`、`fully_visible=False`、`badge_clipped=True`，**字身只剩 11.4 dp（37 px）= 一个字的三分之一**（正常 2 字项字身 36.0~36.6 dp）；
- `dashu` @520 `cand_count=3` —— 第 4 条**一像素都没进视口**；
- VOCA-185 之后翻页器 / 齿轮 / 页码全部移除、`overScrollMode=never`（`c524351`），横滚**没有任何静止态可视线索**。

结论：没有 AC-12，档2 的实际体验是「用户以为只有 3 个词」，然后直接打下一码把后面挤掉 —— 这比 D3 登记的缺陷本身更伤可用性。**所以 AC-12 是档2 的成立条件，不是附带建议。**

**AC-12 不达标时的退路（2026-11-17 质检打回项 1 重写；旧版本这条链有洞）**：

| 面板逻辑宽 | 退路 | 为什么 |
|---|---|---|
| **≥371 dp** | 与本条无关 —— 判据本就是 ≥4，AC-12 只是溢出线索 | 档位口径 |
| **347.5 ~ 371 dp** | **带回 ① 缩 chip**（交前端出实现单，代码让步） | 缺口 ≤23.1 dp 时 ① 补得回来，chip 仍 ≥42.8 dp／4 位满码 —— **旧文字在这里写的是「①② 已证不可达 ⇒ 才动 ④」，这个推断在本带不成立** |
| **<347.5 dp**（含被测档 332.3 dp） | **判 FAIL 并升级人类（PM + 洞察BA）**；**任何情况下都不得指向 ④** | ① 被 4 位底线卡住、② 被 ① 支配、④ 横向增益 0 dp 且同时破 AC-1 与 pp（本单非功能约束禁止项） |

改后的链条仍然**闭合**：档2 从不达标到「有人付出代价」的路径没有断 —— 347.5~371 dp 由 chip 宽度付、<347.5 dp 由「判 FAIL + 人类裁决」付；**唯一被堵死的路径仍是「拿档2 当免费午餐」和「拿档2 当加高的理由」**。旧写法为了制造一个死结，把 ① 的不可达超出了它的成立区间，反而让后来者在 360 dp 这类主流面板上找不到正确退路 —— 自我约束留洞等于没约束。

AC-12 本轮**不进 W5 门槛**（与 AC-11 同处置：不在 PR #18 变更面内，立它进门槛会让闸门凭空多一个 FAIL），交实现单。

## 5. 三角里那条假的边：命中高度 ≥48 dp

规格 §5 旧行写「候选项命中高度 ≥ 48 dp（WCAG 2.2 AA 2.5.8 / Material）」，并把「≥48 命中」与「恒高 46 dp」当作互斥的两条边。**两处都不成立**：

1. **出处误引**：WCAG 2.2 AA 的 **2.5.8 Target Size (Minimum) 是 24×24 CSS px**；44×44 是 **AAA 的 2.5.5**；48 dp 是 **Material 的建议值**。实测候选内容带 38.2 dp 早就过了 24 px 那条线 —— 我们原来在给自己加一条标准没有的要求，还把它当成第三条约束。
2. **恒高内本来就有空间**：46 dp 带 = 上下各 4 dp padding + 38 dp 内容（`minHeight 38dp`）；440 dpi 下 46 dp = 126 px，实测内容 105 px，**21 px ≈ 7.8 dp 的行内余量**可以把触摸命中框从 38.2 dp 抬到 **46 dp**，不动恒高、不动宽度、不动 pp。

**订正后的规格**：硬门限 = **命中高度填满 46 dp 恒高带**；48 dp 降为「不增长度前提下的目标值」，只能在带外上下各 ≤2 dp 的溢出里实现，**须 UI 确认溢出方向与视觉余量后才算达标**，不得为凑 48 dp 改带高。收益：AC-11 的误上屏面同时缩小（有效命中区从 105 px → 126 px 是同一处几何改动，与 slop 修复同批最省）。

## 7. pp：本单不裁，但把口径钉住（防止拿档位一起免掉）

pp 与 AC-10 在第六轮同时 FAIL，**同因不同轴**：同一机制（dp/sp 布局不随物理密度收敛），但候选数对**逻辑宽度**敏感、pp 对**高度比例**敏感。搬到目标真机几何后 **AC-10 翻 PASS、pp 不翻** —— 算法与数字（2026-11-17 质检后订正：**pp 的分母只能是可用高**，与入库值同轴）：

| 口径 | iSpeech | 搜狗 | Δ |
|---|---|---|---|
| **入库实测**（1080×2400@520·fs1.15，可用高 **2340 px**，1 pp = 23.4 px：`ev_r6_pp_window.txt` 头注 + 规格 §1.4） | 1168÷2340 = **49.91 pp** | 1002÷2340 = **42.82 pp** | **+7.09 pp** ✗ |
| **目标几何推算**（1260×2720@520，同 dpi ⇒ IME 高仍是 1168 / 1002 px，Δ 高 = 166 px = **51.1 dp**） | 分母 = 可用高，**未取证** | — | 可用高 ≈2660 px（2720 减系统栏）⇒ **Δ ≈ +6.2 pp**；即便按物理 2720 px 算也只有 +6.1 pp |

**结论不随分母翻转**（166 px ÷ 任一分母都 ≫ 门槛 1 pp），所以本单「AC-10 翻 PASS、pp 不翻」照旧成立；但 §6.5 的本职就是钉 pp 口径，**若沿用物理高，同一帧会得出两个 pp 数**（可用高口径 49.91 pp vs 物理高口径 42.9 pp，差 7 个百分点）—— 已把「分母 = 可用高，不是物理高」写进规格 §6.5 三条口径第 1 条。旧文本里的「1168÷2720 = 42.9 % / 搜狗 36.8 %」是物理高口径，已废弃。

三条口径写进规格 §6.5：① pp 判据必须是**比率或 dp**，不得用模拟器像素高差跨档比较，且**分母只能是可用高**；② **pp 不得用候选条高度来还**（本单非功能约束的反向版）；③ 档位改动**不免除** pp 的账。pp 的修复方向在键区（§6.2 方案 B1：恒高 + 键高 52→46）与工具栏，属**架构 + UI + 前端**的变更，需要 ADR 与真机取证 —— **不在本单范围，建议由 PM 单列一条 R17 后续项**。
