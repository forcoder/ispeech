## 2. 方块键比例

### 2.1 三个口径先分清（全文统一用词）

| 词 | 定义 | 谁在用 |
|---|---|---|
| **键格 cell** | 布局分配的矩形，含四周 3 dp 外边距。**= 可点热区**（UX §5.2） | 验收口径（AC-4.6）、命中判定 |
| **键面 face** | 用户看到的白色圆角块。= cell 四边各内缩 3 dp | **视觉口径**（比例、对比度、投影） |
| **间隙 gutter** | 相邻两个 face 之间的距离 = 2 × 3 dp = 6 dp。露出键盘底色，不属于任何键的「可见面」 | 视觉边界 |

> 这三个数不能混用。AC-4.6 的「≥38 dp」量的是 **cell**（UX §6 R4 已澄清），而用户眼里的块是 **face（32.17 dp）**；把 face 判成 38 dp 会让任何实现都不达标。

### 2.2 参考机型实算（1260 × 2720 px / density 520dpi = 3.25x）

| 量 | 公式 | 值 |
|---|---|---|
| 屏宽 | `1260 / 3.25` | 387.69 dp |
| 可用宽 | `387.69 − 2 × 3`（行内 padding） | 381.69 dp |
| 键格宽 cell | `381.69 / 10`（`LETTER_ROW_UNITS = 10f`） | **38.169 dp** |
| 键面宽 face | `38.169 − 2 × 3` | **32.169 dp** |
| 键面高 face | VOCA-46 基准 | **46 dp** |
| 键格高 cell | `46 + 2 × 3` | **52 dp** |
| **宽高比（视觉口径）** | `32.169 / 46` | **0.699 ≈ 0.70** |
| **宽高比（验收口径）** | `38.169 / 52` | **0.734 ≈ 0.73** |
| 键面面积 | `32.169 × 46` | 1479.8 dp² |
| 圆角半径 / 键面宽 | `6 / 32.169` | 18.7 % |
| 圆角半径 / 键面高 | `6 / 46` | 13.0 % |

**结论：规格写「0.70（面）/ 0.73（格）」，不写 40 dp，也不写 1:1。**

### 2.3 为什么做不到 1:1（不是选择，是约束冲突）

两条硬约束互相排斥：

1. **高度下限 40 dp**（AC-4.6，代码 `MIN_KEY_HEIGHT_DP = 40`）。VOCA-46 取 46 dp。
2. **宽度上限 32.17 dp**（face）。10 列 QWERTY 在 387.69 dp 屏上的物理上限。

| 想做到 1:1 的路径 | 需要的值 | 撞上哪条约束 |
|---|---|---|
| 宽度跟高度走 | face 46 dp → cell 52 dp | 需要 `381.69 / 52 = 7.34` 列；26 键字母必须 10 列（VOCA-30 栅格） |
| 高度跟宽度走 | face 32.17 dp | 低于 40 dp 下限，且 4 行键区从 208 dp 掉到约 153 dp，键盘过矮（VOCA-46 预算外） |

**所以「搜狗白色方块键」在 10 列布局下只能是「近似方块（0.70）」**。观感上的「方」由 §3 的三件套承担，而不是由比例承担。

### 2.4 宽高比目标带（横屏/窄屏/平板都在这一条公式里）

`face宽 = (屏宽 − 6) / 10 − 6`，`比例 = face宽 / 46`。

| 屏宽 | 键格 cell | 键面 face | 比例（46 高） | 判定 |
|---|---|---|---|---|
| 320 dp（窄屏下限） | 31.40 | 25.40 | 0.552 | 偏窄，仍是可读键面；40 dp 不可达（UX §6 R4） |
| 360 dp（主流小屏） | 35.40 | 29.40 | 0.639 | 可接受 |
| **387.69 dp（参考机型）** | **38.17** | **32.17** | **0.699** | **规格值** |
| 412 dp（主流大屏） | 40.60 | 34.60 | 0.752 | 更接近方块 |
| 420 dp（大屏上限） | 41.40 | 35.40 | 0.770 | 接近方块 |
| ≥600 dp（平板全宽） | 59.40 | 53.40 | 1.161 | **反向失衡（扁宽）**，见 §7.3 |

- 不设固定宽高比、不按屏宽缩放字号：比例是屏宽的**结果**，规格只锁「四边内缩 3 dp」这一条。
- 允许区间：0.55（320 dp）~ 0.77（420 dp）。超出区间由 §7.3 的平板规则兜。

### 2.5 内边距（两层，别混）

| 层 | 值 | 令牌 | 说明 |
|---|---|---|---|
| 外框内缩（face 与 cell 之间的留白） | 3 dp / 边 | `key.gutter` | 视觉留白，**不是**不可点区（hit = cell） |
| 文字安全区（字形与 face 边缘的最小距离） | 水平 4 dp / 垂直 2 dp | `key.text.inset.x` / `.y` | 新增。18 sp 单字在 32 dp 宽键里占 18 dp，左右仍各有 7 dp；长文案键（weight > 1.4，15 sp）按此兜 |
| 角标提示内缩 | 上 2 dp / 右 2 dp | `key.hint.inset` | 复用现状（`dpInt(2)`） |

> 文字安全区只约束**最小距离**，不新增 padding 到键面（键面宽不够时允许字形贴边），避免把 18 sp 字挤成 15 sp。

### 2.6 视觉外框定义（给前端的一句话）

**视觉外框 = 键格四边各内缩 3 dp 的圆角矩形，圆角 6 dp（固定值，不随键宽缩放），1 dp 投影向外扩散，投影仍落在键格内。**

- 圆角固定 6 dp 而非按比例：32 dp 宽的键与 135 dp 宽的空格键用同一圆角，才不会出现「小键像药丸、大键像卡片」。
- 9 宫格 T9 页沿用同一令牌：3 列时 face 宽约 121 dp、比例 ≈2.6，跨列键更高；这是 T9 的固有形态，VOCA-30 已明确 T9 不跟 26 键收缩。

### 2.7 能不能更「方」一点（结论：可以，但不属本批）

间隙从 3 dp 收到 2 dp / 1 dp，face 会变宽、比例更接近方块。这是 **VOCA-30 的键间距参数**，本批不改，只留数据供决策：

| 方案 | 间隙 | face 宽 | 比例（46 高） | 代价 |
|---|---|---|---|---|
| A（本批，现状） | 6 dp | 32.17 | 0.70 | — |
| B1 | 4 dp（2 dp 边距） | 34.17 | **0.74** | 改 VOCA-30 的参数；间隙仍可辨 |
| B2 | 2 dp（1 dp 边距） | 36.17 | 0.79 | 间隙接近发丝线，投影成为唯一边界，弱视用户更难分辨 |

**推算参照**：搜狗同机实测键面宽 36.9 dp（`docs/keyboard-ui.md` §2）；用其总高 36.21 %、chrome 96 dp 反推键高约 49.9 dp，比例约 **0.74**——与本表 B1 吻合。

**建议**：本批保持 A（0.70），把 B1 作为后续提案交 VOCA-30 owner（架构/前端）评估，理由是 0.70 → 0.74 更接近用户参照物、且间隙仍在可辨范围。**不建议 B2。**

## 3. 视觉边界：hit 扩到键格之后，靠什么区分键

### 3.1 结论

热区扩到键格（AC-4.1 消死区）之后，键与键之间**只剩 6 dp 间隙可用**。视觉边界由三件事叠加，缺一不可：

| # | 手段 | 具体做法 | 负责什么 |
|---|---|---|---|
| 1 | **间隙** | 6 dp 不填色，直接露出键盘底色渐变 | 给出「两块之间有空」的第一层分隔 |
| 2 | **投影** | 键面 1 dp elevation（现状已存在，`SoftKeyboardView.kt:547`） | 把白面从浅灰底上「抬起来」，补足色差不足（见 §3.2） |
| 3 | **底色差** | 字母 / 标点 / 空格 = 白 `#FFFFFF`；功能键 = 灰 `#C9CDD5`；换行 = 浅蓝渐变 | 区分键**类型**，不是键与键 |

**明确不做**：

- 不画 1 dp 描边把间隙描成「格线」——会读成表格，且与搜狗白键观感相反。
- 不把间隙画成凹槽 / 阴影沟（UX §5.9.3 已禁止：会暗示不可点）。
- 不在间隙里填第三种颜色——8 dp 预算里没有它的位置，且会让按下态难以覆盖。

### 3.2 为什么不能只靠底色差（实测）

| 对比 | 对比度 | 结论 |
|---|---|---|
| 键面 `#FFFFFF` vs 键盘底色顶 `#F4F5F8` | **1.09 : 1** | 远低于 3:1，肉眼几乎不可分 |
| 深色键面 `#2B2F36` vs 深色底 `#1B1D22` | **1.25 : 1** | 同样不可分 |
| 键面 `#C9CDD5` vs 键盘底色顶 `#F4F5F8` | 1.46 : 1 | 功能键与底色几乎同亮度 |

所以「白键浮在灰底上」这件事**完全依赖投影**，不是依赖色差。投影一旦去掉（如低端机禁用硬件加速、或 `elevation` 被父容器裁剪），键盘会退化成一片浅色。规格因此把投影写成**必须项**，并在深色模式换用描边（§3.4）。

> 无障碍说明：键面边界不属于「识别控件所必需的视觉信息」（键名已承担识别），故不强制 WCAG 1.4.11 的 3:1；但为满足 UX §5.9.1（视觉上像键的区域必须都在 hit 内），边界仍必须存在且**不得超出 hit**。1 dp 投影的扩散量（≈1 dp）< 3 dp 内缩，满足。

### 3.3 边界相关令牌与深浅取值

| 令牌 | 浅色 | 深色 | 来源 | 适用 |
|---|---|---|---|---|
| `color.keyboard.bg.top` | `#F4F5F8` | `#1B1D22` | 浅=复用 VOCA-30 | 键盘根背景渐变起点 |
| `color.keyboard.bg.bottom` | `#E3E6EC` | `#121418` | 浅=复用 VOCA-30 | 渐变终点 |
| `color.key.face` | `#FFFFFF` | `#2B2F36` | 浅=复用 | 字母 / 标点 / 空格 / 强调 / 危险键常态面 |
| `color.key.gutter` | `transparent` | `transparent` | 新增（显式） | 间隙，露出底色；**禁止填色** |
| `color.key.shadow` | `#000000` 8 %（`elevation` 1 dp 自带） | `#000000` 45 % | 新增 | 键面投影 |
| `color.key.edge` | `transparent`（0 dp 描边） | `#454B56`（1 dp 内描边） | 新增 | 深色模式的边界替代投影 |

### 3.4 深色模式：机制要换，令牌不换

深色下「投影」失效（黑投影叠在近黑底上，对比增量 < 2 %），因此：

- 浅色：`elevation = 1 dp` + `color.key.shadow`，**无描边**。
- 深色：`elevation = 0 dp` + `color.key.edge` **1 dp 内描边**（描边画在 face 内侧，不改 face 外轮廓，不影响 hit）。
- 两套令牌一一对应，切换只换值、不换布局。

**现状（必须写清，否则会被当成已完成）**：键盘全部色值硬编码在 `SoftKeyboardView.kt:104-134`，`values-night/` 只有窗口主题（`themes.xml`），**键盘本体不跟随深色模式**。本文给出的深色列是「令牌必须同时给」的合规交付，落地需前端新增 `values-night` 颜色资源并让 `SoftKeyboardView` 从资源取色——**属新增能力，不在本批 AC-4.x 验收范围内**（见 §12 R3）。

### 3.5 与 hit 的视觉一致性（硬约束）

1. 投影 / 描边 / 图标 / 角标**全部落在键格内**（外扩 ≤1 dp < 3 dp 内缩）。
2. **间隙里不出现任何「属于某个键」的视觉元素**——否则会暗示该区域属于某键，而实际归属由 UX §5.3 的中线规则决定（中线归左 / 上）。
3. 按下态**不扩展到键格**（§4.2）：用户点在间隙、相邻键亮起时，若高亮铺满整个键格，会误以为「键变大了」。
4. 行首 / 行尾 3 dp padding 保持**不命中**（UX R4-6）；该区域视觉上与间隙同色，不额外画保护带。

### 3.6 如果基线仍是 4 dp 边距（UX §7 C-7 的重算）

VOCA-30 已把 `keyMargin` 从 4 收到 3，旧描述里的「4 dp margin」是过时值。若某分支回到 4 dp：

| 量 | 3 dp（现状） | 4 dp |
|---|---|---|
| 间隙 | 6 dp | 8 dp |
| face 宽 | 32.17 | 30.17 |
| 比例 | 0.70 | 0.656 |
| 底行 1.0 键 face 宽 | 27.78 | 25.78 |
| 死区占比（UX 模型） | 25.4 % | 31.5 % |

边界三件套不变，比例与面积按上表重算；**规格以 3 dp 为准**。

## 4. 按下态、长按预览、禁用态与层级

### 4.1 状态矩阵（视觉列）

| 状态 | 键面 | 文字 | 投影 | 层级 | 触发（交互口径见 VOCA-68） |
|---|---|---|---|---|---|
| 常态 | `color.key.face` / `color.key.special.face` / `color.key.enter.*` | 对应 label 色 | 1 dp | `z.key` | — |
| 按下 | `color.key.face.pressed` | label 色不变 | **0 dp** | `z.key` | `ACTION_DOWN` 在 hit 内 |
| 长按预览（气泡） | `color.bubble.face` | `color.bubble.label` | 4 dp | `z.preview` | 按下非 Shift 键 |
| 长按浮层（字母候选） | `color.bubble.strip` + 条目 `color.key.face` | `color.key.label.primary` 18 sp | 6 dp | `z.alt` | 长按 ≥500 ms（UX Q2） |
| 取消 | 回常态 | 不变 | 1 dp | — | 滑出武装区 >4 dp（UX R4-13） |
| 禁用 | `color.key.face.disabled` | `color.key.label.disabled` | 0 dp | `z.key` | 仅面板 ◀ ▶ 与未来控件（见 §4.5） |

### 4.2 按下态：只覆盖面 + 压下去

| 项 | 规格 | 令牌 |
|---|---|---|
| 覆盖范围 | **只覆盖键面（face），不铺到键格** | — |
| 底色 | 字母 / 标点 / 空格 `#E7E9ED`；功能键 `#BCC1CA`；强调 / 危险 `#DDE4EF`；换行 `#E4EDFF → #D3E1FA` | `color.key.face.pressed` / `color.key.special.face.pressed` / `color.key.accent.face.pressed` / `color.key.enter.top.pressed` 等 |
| 投影 | 1 dp → **0 dp**（面「压平」） | `z.key.pressed` |
| 持续时间 | 0 ms（即时换色，不做过渡；键盘输入要低延迟） | `motion.press` |
| 圆角 | 6 dp 不变 | `key.radius` |

- **投影归零是必需的，不是装饰**：UX §5.11 要求「按下态不依赖颜色单独表达」。底色变深 + 投影消失 = 颜色 + 层次两个通道，色觉障碍用户也能看出「按到了」。
- 按下态**不改变**键面尺寸（不做缩放）：缩放会让相邻键面在视觉上「让位」，与「热区正好等于键格」的认知冲突。
- 换行键按下态保持 1 dp 描边（`color.key.enter.stroke`）不变，只换渐变。

### 4.3 长按预览气泡（不能和白键糊在一起）

现状问题（`SoftKeyboardView.kt:926-950`）：气泡是纯白圆角块、无 elevation，正上方压着同色的白键面——**气泡底边与键面上沿融为一体**，用户看不出气泡从哪开始。

| 项 | 规格 | 令牌 | 变更 |
|---|---|---|---|
| 尺寸 | 高 **40 dp**，最小宽 **38 dp**，内边距 8 / 4 | `bubble.height` / `bubble.minWidth` / `bubble.pad.x` / `bubble.pad.y` | 复用 |
| 底色 | `#FFFFFF` | `color.bubble.face` | 复用 |
| 文字 | 20 sp，`#14171C`，居中 | `color.bubble.label` | 复用 |
| 圆角 | 6 dp | `key.radius` | 复用 |
| **层级** | **elevation 4 dp**（PopupWindow 级） | `z.preview` | **新增** |
| 触摸 | 不接收触摸（`FLAG_NOT_TOUCHABLE`） | — | 交互要求（UX R4-20），视觉侧记录 |
| 描边 | 无（浅色靠投影；深色补 1 dp `color.key.edge`） | `color.key.edge` | 新增（深色） |

**为什么不加描边**：白底 + 1 dp 描边会读成「输入框」而不是「放大的键」；投影既分隔又不改气泡轮廓，且与键面同一套语言。深色下投影失效，才补描边——与键面处理一致。

**与浮层的关系**：气泡（`z.preview`）与字母长按浮层（`z.alt`）不会同时出现（长按到阈值时气泡收起、浮层弹出，UX §4.2）。若实现上两者共存，浮层必须在气泡之上，且气泡不接收触摸。

### 4.4 长按浮层（条目 2，视觉随本批定义）

UX 只给了浮层的交互（顺序 `[小写, 大写, 角标]`、条目 40×40、原样上屏），视觉在本节定义。**这是条目 2 的依赖，不计入条目 4 的 AC-4.x 验收。**

| 项 | 规格 | 令牌 | 理由 |
|---|---|---|---|
| 条目尺寸 | 40 × 40 dp（可点 = 可见） | `control.min` / `control.alt.size` | AC-4.6 独立控件下限 |
| 条底 | `#F4F5F8`（键盘底色顶） | `color.bubble.strip` | **现状是 `Color.WHITE`**：白条 + 白条目 + 2 dp 间距 = 条目边界完全不可见（对比度 1.00:1） |
| 条内边距 | 4 dp | `bubble.inset` | 复用现状 |
| 条目面 | `#FFFFFF`，圆角 6 dp | `color.key.face` | 复用；白条目浮在浅灰条上，与键盘同一语言 |
| 条目文字 | 18 sp，`#14171C` | `color.bubble.label` | 复用现状 |
| 条目按下 | `#DDE4EF` | `color.key.accent.face.pressed` | 复用 |
| 间距 | 条目间 2 dp | `bubble.gap` | 复用现状（小于键间距，因为是浮层内） |
| 层级 | elevation 6 dp | `z.alt` | 新增（高于预览气泡） |

### 4.5 禁用态（新增；键盘本体本批不启用）

全仓没有任何禁用态实现（`isEnabled` / `state_enabled` / `alpha` 0 命中）。本批**唯一真的会用到禁用态的是面板 ◀ ▶**（光标到边界，UX R1-17/R1-18）：

| 项 | 浅色 | 深色 | 令牌 |
|---|---|---|---|
| 面 | `#F4F5F8`（等于键盘底色→「凹陷」） | `#262A31` | `color.key.face.disabled` |
| 文字 / 图标 | `#848B96`（3.15:1） | `#7A8190`（3.68:1） | `color.key.label.disabled` |
| 投影 | 0 dp | 0 dp | `z.key.disabled` |
| 描边 | 无 | 无（`key.edge.width` 也不画） | — |

- 禁用态刻意**低对比**：它要「看起来不可用」，不适用正文 4.5:1 规则（WCAG 1.4.3 对非活动控件豁免）。但**不取到 2:1 以下**——取 3.15 / 3.68，既明显弱于常态（17.96 / 11.15），又保证「这个按钮存在、只是现在不能用」仍可辨。
- 禁用态**不用透明度实现**：整键 `alpha` 会让下方渐变透出来，导致同排键底色不一致；用显式令牌。
- **键盘字母键 / 功能键不设禁用态**：没有任何业务条件会让某个字母不可用；凭空加会创造不存在的状态。

### 4.6 层级表

| 层 | 内容 | elevation | 说明 |
|---|---|---|---|
| 0 | 键盘根背景（渐变） | — | `color.keyboard.bg.*` |
| 1 | 键面 / 工具栏按下块 | `z.key` = 1 dp | 按下时归 0 |
| 2 | 预览气泡 | `z.preview` = 4 dp | 独立 PopupWindow |
| 3 | 长按浮层 | `z.alt` = 6 dp | 独立 PopupWindow |
| 4 | 面板 / 设置浮层 | 系统窗口 | 不在本节 |

### 4.7 为什么没有 loading / error 态

键盘键面与工具栏键**没有异步语义**：字母上屏、退格、切布局都是同步动作。唯一异步的是语音（已有「按住说话」手势与上滑取消的独立视觉，属 VOCA-45），不通过键面 loading 表达。因此本文**不定义**键面 loading / error，并明确记录：这不是漏项，是无适用场景；若将来出现异步键（如云端 AI 键），按 §4.5 的禁用态 + 独立 loading 指示器补充。

## 5. 40 × 40 dp 控件规格

### 5.1 分档规则（先分档，再谈 40 dp）

| 档 | 定义 | 下限 | 成员 |
|---|---|---|---|
| **甲：独立控件** | 尺寸不受栅格竞争，可自由定 | **硬下限 40 × 40 dp** | 工具栏键、搜索 ✕、面板 ◀ ▶、长按浮层条目、候选条按钮 |
| **乙：栅格键** | 宽由屏宽 / 权重决定，无法单独放大 | **下限 = 填满键格**（无可见留白、无死区） | 26 键字母键、底行 1.0 / 1.5 / 1.8 / 4.0 权重键、T9 键 |

> 乙档写 40 dp 会制造一条永远无法通过的门禁（320 dp 屏 10 等分只有 31.4 dp）。AC-4.6 的原文修订已由 UX 在 §6 R4 提出，交洞察BA 回写；本文按「甲 40 / 乙 填满键格」给值。

### 5.2 逐控件取值（参考机型 387.69 dp）

| 控件 | 现状 | 视觉尺寸（face） | 可点尺寸（hit/cell） | 40 dp | 处理 |
|---|---|---|---|---|---|
| 26 键字母键 | 32.17 × 52（高 52） | **32.17 × 46** | 38.17 × 52 | 宽不达 | 乙档：填满键格；AC-4.6 的 ≥38 按 cell 验收 |
| 底行 1.0 权重（`符` `123` `，` `。`） | 27.78 × 52 | **27.78 × 46** | 33.78 × 52 | 不达 | 乙档：填满键格；**需 AC 口径回写** |
| 底行 1.5 权重（Shift / 退格 / 换行） | 44.67 × 52 | 44.67 × 46 | 50.67 × 52 | 达 | 乙档，无需改 |

| 页码条（多页布局） | **22 高 × 全宽** | 22 高 | 22 高 | **不达** | **本批不改**，见 §5.5 |

### 5.3 工具栏：视觉尺寸、对齐与决策 F 的总高账

**视觉规格（两种归属下相同）**

| 项 | 规格 | 令牌 |
|---|---|---|
| 键面 | **40 × 40 dp**，无常态底色（透明，露出键盘渐变） | `control.toolbar.height` / `control.min` / `key.gutter` |
| 图标 | 24 dp 居中；`key_icon_tint` 着色（常态 `#000000`，按下 `#4C7DF0`） | `control.icon.size` / `color.control.icon` / `color.control.icon.pressed` |
| 文字键（`符` 与状态键） | 12 sp，`#14171C`，单行居中 | `font.toolbar` / `color.key.label.primary` |
| 按下 | 40 × 40 圆角 6 dp 块，`#E1E5EC` | `color.control.toolbar.pressed` |
| 选中（面板打开中） | 40 × 40 圆角 6 dp 块，`#3A66D0` + **图标转白** | `color.control.toolbar.selected` / `color.control.icon.selected` |
| 键间距 | 3 dp 边距（与布局行同一 `keyMargin`） | `key.gutter` |
| 行内边距 | 上下 4 / 0，左右 3（与字母行 3 dp padding 对齐） | 复用现状 |
| 横向排布 | 9 键 × 46 dp = 414 dp > 381.69 dp 可视宽 → **横滑**（现状即如此）；首屏左缘与字母行左缘对齐 | 复用 `HorizontalScrollView` |

**关于选中态图标（修正项）**：现状选中态底色 `#3A66D0`，但图标 tint 只定义了 `state_pressed`，选中时仍是黑色（对比度 3.99:1，勉强过 UI 组件 3:1 下限）。规格改为**选中时图标白色**（5.26:1），并在 `key_icon_tint.xml` 补 `state_selected`。这是一条新增状态定义，属本批工具栏规格内的必要修正，不是改配色体系。

**决策 F：工具栏 40 dp 归属未定，两种归属的总高账**

| 归属 | 动作 | 键盘总高变化 | 占 AC-4.7 的 8 dp 预算 | 对 AC-4.6 的影响 |
|---|---|---|---|---|
| ① 纳入 VOCA-46 | 工具栏 face 34 → 40（行高含 4 dp 上内边距：38 → 44） | **+6 dp** | **6 / 8** | 工具栏项达标 |
| ② 移出本批验收（PM 推荐） | 本批不动工具栏高度 | **0 dp** | 0 / 8 | 工具栏项在回写中移出本批；视觉规格保留，待 VOCA-46 落地 |

- 两种归属下**视觉值都是 40 × 40**，前端实现不需要等决策：若走 ① 就改高度，若走 ② 就只改宽度/状态令牌。
- 归属确定后必须回写本表与 AC-4.6，避免「规格写了 40、验收不看」的悬空项。

### 5.4 搜索框 ✕ 与 ◀ ▶（面板，条目 1 依赖）

**约束：不能让搜索行变高。** 现状搜索行高 = `max(✕ 28, caret 18, 文本 18) + 6 + 6 = 40 dp`。若只把 ✕ 放大到 40 高，行高会变成 52 dp（面板固定 200 dp 上限下，列表少约 1 行）。因此配套调整垂直内边距：

| 项 | 现状 | 规格 | 令牌 |
|---|---|---|---|
| ✕ 可点 | 30 × 28 | **40 × 40** | `control.min` |
| ✕ 图标 | 14 dp | 14 dp（不变） | `ic_close` 固有尺寸 |
| ✕ 底色 | 无 | 常态透明；按下 40×40 圆角 6 `#D3D9E3` | `color.panel.control.pressed` |
| ✕ 空态 | `GONE`（布局跳） | `INVISIBLE` 保留槽位（UX R1-19） | — |
| ◀ ▶ 可点 | 不存在 | **40 × 40**，图标 24 dp（复用 `ic_cursor_left` / `ic_cursor_right`，需 tint） | `control.min` / `control.icon.size` / `color.control.icon` |
| ◀ ▶ 禁用 | 不存在 | 见 §4.5 | `color.key.face.disabled` / `color.key.label.disabled` |
| 搜索行垂直内边距 | 6 / 6 | **0 / 0** | `panel.search.pad.y` |
| 搜索行高度 | 40 | **40（不变）** | — |
| 搜索行水平内边距 | 12 / 6 | 12 / 6（不变） | `panel.search.pad.x` |

**宽度账（参考机型，面板全宽）**：固定件 = 12（左内距）+ 14（🔍）+ 4 + 3（caret）+ 23（中/英徽标）+ 40×3（◀ ▶ ✕）+ 6（右内距）= **182 dp**，文本区剩 **≈ 206 dp**。

- 20 个汉字 @14 sp ≈ 280 dp > 206 dp → **必须依赖 UX R1-28 的横向滚动**，视觉上不压缩 ✕ / ◀ ▶ 来给文本让位。
- 320 dp 窄屏：文本区 ≈ 138 dp（约 9 汉字），滚动频繁。这是条目 1 的已知窄屏代价，记录在 §12 R6；若产品不接受，需删「中/英」徽标（属 UX 决策，不在此处改）。

### 5.5 页码条 22 dp：记录，不在本批修

`PAGE_BAR_HEIGHT_DP = 22` 且可点（「点此翻页」，`SoftKeyboardView.kt:396-410`）。它是**可点控件但只有 22 dp 高**，按甲档标准不达标。

- 本批不改：抬到 40 dp 会让键盘总高 +18 dp，直接击穿 AC-4.7 的 8 dp 预算。
- 处置建议：并入 VOCA-46（其候选条单行改造会重排顶部 chrome），或单开 issue 做「页码条改为键区内翻页控件」。**本文只登记，不扩大范围。**

## 7. 响应式规则

### 7.1 断点

| 断点 | 屏宽 | 代表机型 | 键格 cell | 键面 face | 比例 | 布局变化 |
|---|---|---|---|---|---|---|
| XS | 320–359 | 320 dp 小屏 | 31.40–35.00 | 25.40–29.00 | 0.55–0.63 | 面板文本区 ≈138–166 dp；工具栏必横滑；底行 `符/123/，/。` 键面 21.8–25.4（可读下限） |
| S | 360–411 | 360 / 393 dp 主流 | 35.40–40.50 | 29.40–34.50 | 0.64–0.75 | 与参考机型同构，不特殊处理 |
| **M（参考）** | 387.69 | 1260 px / 3.25x | **38.17** | **32.17** | **0.70** | 本文所有实算以此为准 |
| L | 412–599 | 412 / 420 dp 大屏 | 40.60–59.30 | 34.60–53.30 | 0.75–1.16 | 键面更方；≥480 dp 起进入 §7.2 的内容宽约束 |
| Tablet | ≥600 | 平板 | 内容宽 ≤480 | ≤41.40 | ≤0.90 | **键区内容宽上限 480 dp，水平居中**；工具栏不再横滑 |

### 7.2 宽度规则（一条公式，不设固定比例）

```
可用宽 = min(屏宽, 480) − 2 × key.gutter
cell  = 可用宽 / 10
face  = cell − 2 × key.gutter
比例  = face / key.height
```

- **为什么封 480 dp**：`≥600 dp` 全宽时 face 53.4、比例 1.16，键变成扁宽条，与「方块键」诉求反向。480 dp 时 cell 47.4 / face 41.4 / 比例 **0.90**，是 10 列布局能给出的最接近方块的值，且 9 键工具栏（9 × 46 = 414 dp）可一屏放下、不横滑。
- 封顶后两侧留白由键盘底色渐变填满，**不画任何分隔**；工具栏与候选条共用 480 dp 内容宽 + 左右 3 dp 内边距，面板搜索行同宽但保留自己的 12/6 内边距，四者左缘对齐。
- 字号**不随屏宽缩放**（sp 固定），避免 320 dp 上字被压小、平板字被放大。

### 7.3 平板与横屏

| 项 | 规则 |
|---|---|
| 键区内容宽 | ≤480 dp，居中；底行 7 键按同比例收缩 |
| T9 九宫格 | 3 列，face 宽跟随内容宽（480 时约 152 dp），比例 ≈3.3，属预期，不与 26 键统一 |
| 横屏 | 同 Tablet 规则（横屏可用宽通常 >600 dp）；**不因横屏降低键高** |
| 候选条 / 面板 | 同 480 dp 内容宽与 3 dp 内边距；面板高度上限（200 dp）不变 |

### 7.4 文字缩放（fontScale）

参考机 `fontScale = 1.15`。规则：

- 18 sp 字母在 32.17 dp 键面里，单字最宽 18 sp × 1.15 ≈ 20.7 dp，左右仍余 ≈5.7 dp，**容纳无问题**。
- 有效字号上限 = **23.4 sp**（派生值：`face 32.17 − 2 × key.text.inset.x` = 24.17，取 23.4 同时等于 `18 × 1.3`）。`fontScale > 1.3` 时字母键按上限截断，不再放大。
- 提示角标 8 sp 不参与截断（它更小，永远放得下）；空格 13 sp 同上。
- 字号截断只作用于**键面文字**，不作用于候选条 / 面板（那两处有独立布局，可换行）。

### 7.5 键盘高度不受屏宽影响

除工具栏（决策 F 的 ±6 dp）外，本批**不改变任何高度**：键高 46 dp（VOCA-46）、行数 4、工具栏 40/34 dp、候选条单行。AC-4.7 的 8 dp 预算只被工具栏这一项消耗，详见 §5.3。

## 8. 动效规范

键盘是高频输入工具：**能用 0 ms 就不要动**。本批只为两个真正需要「说明来源」的浮层保留过渡。

| 触发 | 属性 | 时长 | 曲线 | 说明 |
|---|---|---|---|---|
| 键按下 / 抬起 | 底色、投影（1 ↔ 0 dp） | **0 ms**（`motion.press`） | — | 即时切换，不做 cross-fade；输入延迟优先 |
| 工具栏按下块 | 底色出现 / 消失 | 0 ms | — | 与键面同规则 |
| 工具栏选中（面板打开） | 底色、图标 tint | 0 ms | — | 结果状态，不是过程动画 |
| 预览气泡出现 | opacity 0 → 1，translateY `motion.lift` → 0 | **90 ms**（`motion.bubble.in`） | ease-out | 让气泡「从键上长出」，位移仅 2 dp（`motion.lift`），不遮挡邻键 |
| 预览气泡消失 | opacity 1 → 0 | **70 ms**（`motion.bubble.out`） | ease-out | 消失比出现快，减少残影 |
| 长按浮层出现 | opacity 0 → 1，translateY `motion.lift` → 0 | **120 ms**（`motion.alt.in`） | ease-out | 浮层内容更多，稍慢一点更稳 |
| 长按浮层消失 | — | 0 ms | — | 选字后必须立刻消失，不能拖 |
| 面板展开 / 收起 | — | 系统窗口动画 | — | 不在本批 |

**缓动曲线**：`motion.easing` = `cubic-bezier(0.2, 0, 0, 1)`（Android `PathInterpolator(0.2f, 0f, 0f, 1f)`）——快出慢收，适合小位移。出现时上移 `motion.lift` = 2 dp。

**硬约束**

1. 单次交互动效 **≤ 300 ms**；本批最长 120 ms。
2. **禁止**：键面缩放（会与「热区 = 键格」的认知冲突）、弹簧 / 回弹、循环动画、`animateLayoutChanges`、按下时的长按抖动。
3. **可关闭**：系统关闭动画（`ANIMATOR_DURATION_SCALE = 0` 或无障碍「移除动画」）时，全部时长降为 0 ms；**颜色与投影变化必须保留**（它们是无障碍的按下反馈，不能随动画一起关掉）。
4. 动效不得改变可点区域：气泡 / 浮层动画期间 `FLAG_NOT_TOUCHABLE`（UX R4-20），位移只在视觉层。

- 焦点环 = **face 内侧 2 dp 描边**（`focus.ring.width`），色 `color.focus.ring`，圆角跟随 `key.radius`（6 dp）；画在内侧意味着**不改变键面外轮廓、不外扩、不影响 hit**。
- 与换行键 1 dp 描边重叠时，焦点环**在外层优先显示**（换行描边让位，颜色不变）。
- 文字安全区（4 / 2 dp）≥ 焦点环宽（2 dp），因此焦点态不会压到字形。
- 键盘本体目前无焦点态实现（全仓无 `state_focused` 键样式），属新增能力，与 R3 一并落地。
