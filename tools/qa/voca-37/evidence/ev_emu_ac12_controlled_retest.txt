# VOCA-37 · 受控复测（n≥3、同一宿主、交替装包）· emulator-5554 · 2026-11-24 13:0xZ

## 0 结论先行

`d59c375` 交付的 AC-12 实现**在模拟器上把键盘顶出屏幕**，这是**实现缺陷，不是 AVD 噪声**。
根因是 `candidate_view.xml` 里 `candidate_overflow_cue` 用了 `layout_height="match_parent"`，
而它的父 `FrameLayout` 是 `wrap_content`：`AT_MOST` 下这个孩子会拿到「整块可用高度」
（`View.getDefaultSize` → `specSize`），反过来把父撑满 → IME 窗口 `[0,158][1260,2720]`、
键面白像素 14855→19、候选带被量成 738.5dp。改成 `0dp` + 布局后按滚动区实测高度补齐，
同一条件下恢复到 46.2dp / 白像素 14855 / 回读 `shijian`，AC-12 判据转 `FADE_PRESENT`。

上一轮 10:29Z 把这条读数记成「AVD 本身会丢 showSoftInput ⇒ 只当待查信号」，归因错了：
AVD 确实也会丢 IME，但那是**另一种形状**（见 §3），与被测包无关。

## 5 AVD 自身的两种「丢 IME」，与被测包无关

不加就绪闸门时，任何包都会周期性落进这两种形状之一：

```
(a) frame=[0,0][0,0] visible=false      —— IME 窗口根本没出来（mInputShown 可能仍为 true）
(b) 当前方法被换回 LatinIME             —— q2_AC12 实测 mCurMethodId=...latin.LatinIME
```

本轮实测样本：`q1_BASE` boot1 落 (a)、`q3_BASE` boot1 落 (b)、`q2_FIX`/`q5_FIX`/`q6..q8` 批次
全部落 (a)。**两种形状都出现在对照包上**，所以它们不构成对被测包的指控；反过来，
被测包的症状是**第三种**：窗口可见、方法正确、但高度 = 整块面板 —— 这个只在缺陷包上出现。

## 7 工装侧同步修掉的两个量法缺陷

1. **`find_bar` 阈值 0.60 → 0.40**：有候选的行纯底色只占 40–56%（chip + 字身 + 角标吃掉其余），
   0.60 把健康帧切成 8.3–20dp 假条带。降到 0.40 才量到 46.2dp。
   **不能**改用「底色容差族」提覆盖率 —— 键面白 `(240,240,243)` 与 `#F4F5F7` 只差 5，
   任何装得下 chip 铺底（差 31）的容差都会把整块键面算进来，实测条带涨到 719–837dp。
2. **渐变判据**：旧判据要求「线索区内 0 个非底色像素」才能判 `FADE_PRESENT`，
   这与「渐变」本身相反 —— 真有渐变时恒判 `FADE_ABSENT`。改为量斜坡（§4）。
   旧判据下修好的包也是 `FADE_ABSENT`，会再次把实现缺陷误判成「没做」。
